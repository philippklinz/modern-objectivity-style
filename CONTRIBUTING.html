Contributing to Modern Objectivity

Contributions should make the language clearer, more applicable, technically grounded, and easier to verify.

Contribution model

Explain problem → rationale → proposal → alternatives → verification → limitations. Design rules should name their scope. Provide illustrative examples or documented evidence; never imply a hypothetical test has been performed.

Editorial requirements

  • Maintain English as the authoring source for this repository. Publish the complete style guide, handbook, examples and reader-facing contributor guidance in all 24 official EU languages.
  • Write so a new reader can understand the guidance without external context.
  • Exclude company identities, confidential applications, private project notes, or chat references.
  • Distinguish a design language from a brand, UI theme, component library, and software framework.
  • Avoid invented performance benchmarks, accessibility certifications, universal emotion claims, or unsupported superiority claims.
  • Consider technical feasibility, accessibility, ethics, and subjective human experience.
  • Respect copyright and attribution for external research, text, and imagery.
  • Update cross-links, examples, and templates when changing a principle.
  • Apply MO-13 to the whole published guide as well as adopting applications. Published technical documentation is part of that coverage; English source files are an authoring choice, not a publication exemption.

Translation maintenance

Edit the English Markdown or keyed source messages first, then reconcile the affected translations and regenerate published pages. Keep headings, link labels, tables, image descriptions and explanatory prose within the translation inventory. Preserve executable code, API identifiers, original bibliographic titles and the authoritative GPL text; translate the surrounding explanations.

Before release, check all published pages and examples against the complete 24-language inventory, source revisions, placeholders and navigation. Check dynamic feedback and accessible names as well as initial text. Record these mechanical checks separately from linguistic review: the current translations are AI-assisted and await independent language review. Do not mark a translation current merely to silence a failing check.

Preserve principle IDs where possible. If a definition changes materially, document compatibility implications.
