# 06 — Stage & Identity

## One language, different stages

A **stage** is a designed environment for a specific product or experiment. It has its own layout, typography, navigation, timing, and character. A quiet information interface and a visually immersive science exhibit can share Modern Objectivity without looking alike.

The **set** is content and its contextual expression. The **performance** is the running experience, including interaction and time.

## The stage contract

Document three levels:

| Level | Meaning | Example |
| --- | --- | --- |
| Invariants | Consistent behavior within a defined environment | Navigation, state semantics, focus |
| Variables | Controlled alternative configurations | Density, typography, semantic themes |
| Expressive freedoms | Content-specific artistic or educational treatments | Diagrams, spatial scenes, animation |

A rule binding one host application does not automatically bind unrelated projects.

## Modular systems

A host can own navigation, basic controls, permission semantics, feedback, and shared component contracts. Modules provide domain content, specialized actions, and purpose-built visualizations.

An extension may add a novel scientific chart while retaining established search and error behavior. Specialization should not force users to relearn universal interactions.

## Identity without arbitrary novelty

Distinctiveness can arise from proportions, information architecture, typography, imagery, materials, and temporal behavior. Replacing familiar controls with unfamiliar ones merely to appear original is rarely useful.

## Documenting a stage

Every stage should describe purpose, audience, invariants, variables, expression, accessibility alternatives, Emotional Intent, adverse effects, and validation method.
